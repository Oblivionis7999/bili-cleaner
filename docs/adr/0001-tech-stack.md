# 技术栈：本地单进程 Web 应用（FastAPI + 原生前端），PyInstaller 打包

我们选择"本地单进程 Web 应用"作为交付形态：用户双击启动，程序在 `127.0.0.1` 起一个 FastAPI 服务并自动打开浏览器；前端是**无构建链**的原生 HTML/CSS/JS，由同一个进程托管；发布时用 PyInstaller 打成单文件 Windows exe。数据全部落本地文件（JSON/JSONL/CSV），不引数据库。

考虑过并放弃：
- **Electron**：界面自由度更高，但 100MB+ 体积、Node 构建链、升级维护复杂，与"小而美"目标冲突。
- **PySide/PyQt 桌面 GUI**：原生感强，但表格/批量勾选这类高密度交互的开发成本明显高于网页，且跨平台打包麻烦。
- **纯 CLI**：最简单，但目标用户是"想清理账号的普通用户"，命令行不友好。

这个选择的代价：用户机器上必须能跑浏览器（Windows 自带 Edge 即可）；exe 体积约 20–30MB；"看起来不像原生软件"。我们接受这些代价，换取开发速度、界面可控和跨平台潜力（macOS 用户装 Python 也能跑源码版）。
