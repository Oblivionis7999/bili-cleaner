# 删除前强制备份，且不承诺可恢复

任何删除类任务在发出第一个写请求前，必须先把待删对象导出为两个文件：`CSV`（人看：标题/UP/链接/时间）和 `JSONL`（完整字段，供以后写脚本用），默认放在 `%APPDATA%\BiliCleaner\backups\<账号>\<时间戳>\`。备份失败则任务直接失败，不允许"跳过备份继续删"。

"清空"类操作（清空收藏夹、清空稍后再看、清空动态）还要用户在输入框里手打确认词"清空"才能提交。取关类操作要求用户勾选"我已了解取关后无法恢复原关注顺序"。

明确不承诺的部分：B 站侧删除不可撤销，工具不提供"恢复删除"功能。备份的意义是"以后想知道删了什么/写脚本重新加回来时有数据"，而不是"一键还原"。

考虑过并放弃：备份进 SQLite（查询方便，但引入数据库依赖，且备份要能脱离工具打开）；可选备份（公开工具面向不安全用户，默认可跳过等于把风险外包给用户）。代价是每次删除都要多花几秒写文件、磁盘占用增长——我们接受，并在设置里提供"保留最近 N 次备份"的清理选项（默认保留全部）。
